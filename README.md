# شورای هوش مصنوعی (AI Boardroom) 🏛️

اپلیکیشن اندروید بومی (**Kotlin + Jetpack Compose**) برای برگزاری جلسات مشاوره‌ای با کارگروه‌های هوش مصنوعی. این ابزار برای **سازمان‌ها و شرکت‌ها** طراحی شده است — الگوی آن مانند یک **وزیر و کابینه‌اش** است: کاربر به‌عنوان **رییس جلسه** (مدیرعامل/وزیر) مسئله را مطرح می‌کند و کارگروه‌های تخصصی — هر کدام با ۵ مشاور هوش مصنوعی — مانند اعضای کابینه تحلیل و گزارش ارائه می‌دهند.

> این فایل README همان سند مرجع پروژه است (نقش handoff را دارد). سند جداگانه‌ای با نام HANDOFF وجود ندارد؛ هرگونه ادامهٔ کار روی پروژه باید از همینجا شروع شود.

---

## ۱. وضعیت فعلی پروژه

- **مبدأ کد:** این ریپو. سورس کامل اپ در پوشهٔ `ais-mittings/` قرار دارد (پروژهٔ Gradle استاندارد Android).
- **ادغام انجام‌شده:** دو نسخهٔ قبلی پروژه («Ais mittings» و «ai-meeting») با هم ادغام شدند؛ نتیجه همان سورس `ais-mittings/` است به‌علاوهٔ قابلیت «کارگروه پویا» که از نسخهٔ ai-meeting منتقل شد.
- **ساختار کارگروه‌ها پویا شد:** پیش‌تر ۲۰ کارگروه ثابت وجود داشت؛ اکنون **پیش‌فرض ۴ کارگروه سازمانی** (استراتژی و برنامه‌ریزی 📈، فناوری و نوآوری 💻، مالی و منابع 🏦، حقوقی و انطباق ⚖️) ساخته می‌شود و کاربر می‌تواند هر تعداد گروه **افزودن یا حذف** کند. ساختار، عملکرد و روش وارد کردن مدل‌های هوش مصنوعی در همهٔ گروه‌ها یکسان است؛ افزودن گروه جدید عملاً یک «کپی» از الگوی استاندارد گروه (۵ جایگاه مشاور) است و برنامه را شلوغ یا سنگین نمی‌کند.
- **بیلد خودکار:** workflow آمادهٔ `Build AI Boardroom APK` در فایل `build-apk-workflow.yml` (در ریشهٔ ریپو) آماده است. برای فعال‌سازی، یک‌بار آن را در مسیر `.github/workflows/build-apk.yml` روی شاخهٔ `main` قرار دهید (از طریق وب‌سایت GitHub: فایل را بسازید و محتوای `build-apk-workflow.yml` را در آن کپی کنید). از آن پس با هر push به `main` یک APK دیباگ ساخته می‌شود (خروجی در تب **Actions › آخرین run › Artifacts**). برای بیلد محلی: پروژهٔ `ais-mittings/` را در Android Studio باز کنید و `./gradlew :app:assembleDebug` را اجرا کنید.

## ۲. امکانات اصلی

### کارگروه‌های پویا
- تعداد کارگروه‌ها توسط کاربر تعیین می‌شود (پیش‌فرض ۴ گروه).
- **افزودن گروه:** دکمهٔ «➕ افزودن گروه» در انتهای نوار پایین → نام، رنگ، آیکون و عناوین ۵ جایگاه را انتخاب کنید (۵ پیش‌تنظیم آماده هم دارد).
- **حذف گروه:** تنظیمات کارگروه (کلیک روی پنجرهٔ گروه) → دکمهٔ «🗑 حذف کارگروه» با تأیید دومرحله‌ای. آخرین گروه باقی‌مانده حذف نمی‌شود و کلیدهای API گروه حذف‌شده به‌صورت امن پاک می‌شوند.
- هر گروه ۵ جایگاه مشاور دارد؛ برای هر جایگاه می‌توانید: نام اختصاصی، نوع/نام مدل (**Google Gemini، OpenAI GPT، Anthropic Claude، سرور Ollama، REST سفارشی**)، کلید API اختصاصی و آدرس سرور محلی (برای Ollama) تعیین کنید.

### چهار حالت تصمیم‌گیری (Dispatch Modes)
1. **تشخیص خودکار (Auto Triage):** کارگروهِ مسئول ارجاع (قابل تغییر از تنظیمات) مسئله را تحلیل و به ۱ تا ۳ کارگروه مرتبط ارجاع می‌دهد.
2. **انتخاب دستی (Selective):** رییس جلسه خودش کارگروه‌های شرکت‌کننده را برمی‌گزیند.
3. **جلسه علنی (Public Assembly):** همهٔ کارگروه‌های مجاز نظر می‌دهند.
4. **زنجیره‌ای (Sequential Pipeline):** خروجی هر کارگروه ورودی کارگروه بعدی می‌شود (ترتیب از «ویرایشگر زنجیره» قابل تعیین است).

### حافظهٔ داخلی (Memory Engine)
- پوشهٔ **master** مشترک: منشور، خط‌مشی‌ها و اسناد کلان — در دسترس همهٔ اعضا در همهٔ جلسات (قابل مدیریت از تنظیمات).
- پوشهٔ اختصاصی هر جلسه: متن کامل مذاکرات، گزارش تفکیکی کارگروه‌ها و صورت‌جلسه (`meeting_minutes.md`).
- مسیر ریشهٔ حافظه از تنظیمات قابل تغییر است.
- در ابتدای هر جلسه، حافظهٔ master + خلاصهٔ جلسات قبلی به پرامپت همهٔ اعضا تزریق می‌شود.

### ورودی چندگانه رییس جلسه
متن، **دیکشنقل صوتی** (SpeechRecognizer با مجوز میکروفون) و **پیوست فایل** (تا ۵ مگابایت؛ فایل در پوشهٔ جلسه ذخیره می‌شود).

## ۴. امنیت کلیدهای API (قانون تخطی‌ناپذیر)

- کلید API هر جایگاه **فقط** در `SecureKeyStore` (رمزنگاری‌شده با Android Keystore) ذخیره می‌شود.
- `subAgentsToJson` کلید را قبل از ذخیره در Room پاک می‌کند — کلید هرگز وارد دیتابیس/دیسک معمولی نمی‌شود.
- دیتابیس و Keystore از قوانین Backup اندروید مستثنی هستند (`backup_rules.xml`).
- با حذف یک کارگروه، کلیدهای آن گروه هم پاک می‌شوند.

## ۵. چیدمان UI (تأییدشده — بدون هماهنگی تغییر ندهید)

- **یک نوار افقی در بالای صفحه:** پنجرهٔ همهٔ کارگروه‌ها (تعداد پویا) + کارت «➕ افزودن گروه» در انتهای همان نوار.
- **پنل چت یکپارچهٔ تمام‌عرض** زیر نوار: بالا = جریان یکپارچهٔ پیام‌ها (پیام‌های رییس جلسه، گزارش کارگروه‌ها و بیانیهٔ نهایی)؛ پایین = نوار ورودی متن/صدا/فایل. صفحهٔ نتایج جداگانه وجود ندارد — خروجی نهایی جلسه به‌صورت پیام «بیانیه و مصوبات نهایی» در همان جریان چت نمایش داده می‌شود و گزارش تفصیلی هر کارگروه از کلیک روی پنجرهٔ همان گروه باز می‌شود.
- آیکون تنظیمات در گوشهٔ بالا-چپ؛ **تمام توضیحات فنی فقط داخل دیالوگ تنظیمات** قرار دارند.
- Activity با `configChanges` مانع نابود شدن هنگام چرخش صفحه می‌شود.

## ۶. اتصال به Ollama (مدل محلی)

اپ اندروید نمی‌تواند خودش سرویس CLI نصب کند؛ Ollama باید روی یک سرور/PC در شبکه (یا همان گوشی، مثلاً با Termux) در حال اجرا باشد و اپ فقط به آدرس HTTP آن وصل می‌شود:

- Ollama روی **PC در شبکهٔ محلی**: در فیلد سرور جایگاه مشاور `http://<IP-کامپیوتر>:11434` بدهید.
- Ollama روی **همان گوشی** (مثلاً Termux): `ollama serve` را اجرا کنید و آدرس `http://127.0.0.1:11434` را بدهید.
- روی **شبیه‌گر اندروید**، سرورِ PC خودِ میزبان با `http://10.0.2.2:11434` قابل دسترسی است.
- ترافیک HTTP بدون رمزنگاری مجاز است (`usesCleartextTraffic`)؛ کلید API برای Ollama لازم نیست ولی اگر تنظیم شود به‌عنوان Bearer ارسال می‌شود.

## ۷. نکات بیلد و توسعه

- **minSdk 24 / targetSdk 36 / Kotlin + Compose Material 3 + Room (KSP) + Retrofit/OkHttp + Moshi.**
- برای بیلد لوکال، `GEMINI_API_KEY` را در `.env` نگذارید — کلیدها را داخل خود اپ (تنظیمات هر جایگاه) وارد کنید.
- تغییرات دیتابیس با `fallbackToDestructiveMigration` انجام می‌شود؛ با تغییر entityها نسخهٔ DB را بالا ببرید.
- **گم‌شده/باز‌نویسی‌نشده:** ذخیره‌سازی حافظه روی GitHub/Google Drive (که در نسخه‌ای قدیمی «فاز ۸» بود) در سورس فعلی وجود ندارد و در صورت نیاز باید از نو پیاده‌سازی شود (نیازمند GitHub PAT و پروژهٔ Google Cloud برای Drive OAuth از طرف کاربر است).
- فایل‌های zip قدیمی و آرتیفکت‌های بلااستفاده از ریشهٔ ریپو حذف شده‌اند؛ سورس `ais-mittings/` مرجع واحد است.
